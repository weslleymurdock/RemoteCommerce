# Stage Template

## Goal

Describe the user-visible capability and the architectural outcome.

## Scope

List the implementation boundaries. Avoid mixing unrelated features into one stage.

## Required changes

- Domain/model changes.
- Application/services changes.
- UI/API changes.
- Persistence changes.
- Plugin contracts, if applicable.
- Tests and validation.
- Documentation.

## Acceptance criteria

Use observable, testable criteria. Include a build of the affected solution and isolated builds for generated plugins/tools when applicable.

## Compatibility

Document API versions, migration concerns, plugin compatibility, and configuration changes.

## Exit condition

State the condition that permits the PR to be integrated and the next stage to start.
